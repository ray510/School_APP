## 家長角度的改動

### 先揀需要，再看答案

家長選入學學年、K1/K2/K3、上午／下午／全日班、地區及校名，可補充希望接走時間及全年預算。主介面不要求家長理解資料來源代碼、JEV 狀態或機率。

目前地區及校名實際篩選清單；年級／班別決定展示哪些收費。預算及接走時間在詳情／比較用來解讀已知資料，不是已完成一套自動排除或學校推薦引擎。缺資料不當成不符合，也不因學校網頁寫得多而排名較高。

### 三個主要答案

1. **點報名**：已核對的本校適用學年公告、步驟及來源；未核對則明示要向學校問甚麼。共同程序與個別學校申請日期分開。
2. **要畀幾多錢**：指定年級／班別的學費及膳食、各自期數及本版已知小計。註冊費不重複加算，校車、用品及延長照顧未齊時不聲稱完整全年總額。
3. **接送時間夾唔夾**：同學年正常時間有證據才對照家長需要；辦公時間、全日班登記、課室容額及延長照顧不混用。

比較页首先顯示「一眼看出要確認嘅差異」，再提供每日點學、適應同支援、報名要留意、接送照顧四個面向。原文及資料方法可展開，完整來源依然可查。舊 `/schools` 與 `/compare` 保留；新家長流程請使用 `/kindergarten`，不聲稱所有舊網址都改為自動跳轉。

私人清單沿用 IndexedDB。可把具體查詢問題加入筆記，手動標記準備／已申請／等通知等進度；不替家長交表，不上傳私人筆記或兒童證件。備份仍經原有私人清單的匯出／匯入入口。

## JEV 如何協助家長

模型 `jev-1.13.0`、policy `kg-parent-evidence-v1`，以幼稚園概覽完整欄位及已連接公開背景作输入，從指定原文欄位挑選相關證據。四個問題面向為每日學習、入學適應／支援、報名及照顧。展示的引文由程式逐字核對；後續查詢問題由規則模板提供，不冒稱模型產生新學校事實。

原始推論在 run `35454325243`、commit `10a38b87ae120c602964b9cefab4b6d2c8bafa18` 已完成。本次只有在輸入逐位元組相同、模型／policy／來源hash均符合時重用結果。

- 962筆：ANALYZED 961、UNAVAILABLE 1（回應格式無效）。
- 有效回應中的四面向：SUPPORTED 1,267、REVIEW 1,450、NOT_ESTABLISHED 1,127。這些是選項狀態，不是學校數。
- 2,717段引用逐字吻合，包括待覆核引文；吻合不等於語義判斷必然正確。
- 原推論963次請求，回報10,685,875輸入tokens、869,549輸出tokens。
- 依該次記錄價目估算US$0.448807，預算US$0.80；不是完整帳單或目前價格承諾。
- 本次恢復發布新增模型請求 **0**，沒有重複花費上述費用。
- `NOT_HUMAN_CALIBRATED` 保留；模型canary只驗證契約，不是學校準確率驗證。

日期、資助分類、費用算式及時間對照由確定性程式處理；不讓JEV估剩餘學位、改寫費用、判定家庭資助資格或推測兒童是否適合。
